# Animation: adaptive video and motion production

Turn the user's intent into a finished result with a proportionate acceptance check. Use `$animation`; no dependency on invoking `01`, a particular model, editor or animation style. A simple edit can go straight to execution. Do not make every request a research project, concept deck, team or new pipeline.

## Choose the work that matters

Start with the audience, purpose, supplied source and destination. Establish what must be delivered and remain editable: a cut, film, explanation, animation, release package, loop/rig/overlay or interactive experience. For existing work, inspect the actual native project and representative media; improve its limiting factor while preserving useful structure. Ask only for missing inputs that materially change the result. Choose unspecified creative details yourself.

Connect the promise to what the audience actually sees or hears. A title, opening, demonstration and ending should belong to the same idea. Choose narrative, staging, camera, performance, visual language and sound for the subject; adapt rhythm to the material. When uncertainty or generic output justifies exploration, compare distinct treatments through small boards, poses or motion beats, then choose and finish. For a costly multi-shot film, test a representative action and its key cut before committing the full sequence. Judge causal progression, contact, spatial continuity and the payoff in order, not only the strongest still. For recurring subjects or shot revisions, preserve a small [continuity reference](references/styles-and-techniques.md#preserve-visual-continuity) and compare the actual adjacent images. Use references for specific qualities rather than imposing their house style. A technically valid export is not evidence of a compelling edit. For dynamic work, build progression through visible actions and consequences, with readable holds. Vary emphasis for the material instead of cycling every scene through the same entrance, pause and exit. See [purposeful motion](references/purposeful-motion.md) when motion direction is the limiting factor.

## Adapt the execution

Do connected work directly. Delegate separable research, craft, implementation or review when the gain earns the coordination cost. Give each specialist the objective, inputs, constraints, owned scope and expected artifact/evidence. Resolve disagreement against source material, viewer response or a discriminating probe, not votes. Preserve the user's chosen model/effort; model-specific recipes and role assignments are revisable defaults, never permanent requirements.

Use the appropriate existing native tools and skills first. Choose or combine techniques by quality, control, editability, iteration cost and receiving-system compatibility. For a genuine missing capability, use [discovery](references/discovery.md), inspect current primary sources and prove a viable free route before depending on it. A list, install, feature claim or historical receipt does not establish a working session. Reconsider the approach when observations contradict it; stop retries that no longer improve evidence.

## Iterate and finish

Retain prior versions. Identify changed sources and affected cuts, shots, takes or assets; reuse only verified unchanged dependencies. Match timing to the artifact: offline work needs repeatable evaluation/bakes; interactive/live work needs explicit input/state and pause/replay behavior. Keep long-task state beside its artifacts with the objective, constraints, decisions, changed sources, evidence, unresolved items and next action. Use native continuation and bounded owned jobs; the local production profile explains resource limits and checkpoints.

Judge the actual result against this brief. For a requested motion or sound review, first establish that the reviewer can receive those modalities; use the [review fallback](references/production.md#perceptual-review-and-feedback) when access is missing. Inspect final images, cuts, motion, text and sound, with normal-speed viewing/listening where available. Use relevant checks for duration/frames/sync, loop/alpha, factual claims, input behavior, missing media or receiving-side editability. A fresh reviewer is useful when independent interpretation can expose consequential ambiguity or defects. Fix material findings; repeat or broaden checks only for a failure, new change or unresolved risk. Distinguish passed, failed and unavailable evidence.

Deliver the requested media/assets, usable native sources, necessary dependencies/terms and concise reproduction/recovery information. Include release assets only when in scope. Preparing local drafts is distinct from uploading, publishing, scheduling or contacting anyone; preserve the user's actual authorization for those actions. Leave one clear entry point identifying selected masters and remaining limits. If blocked, state the precise missing input/control and completed work. Further optimization needs a plausible material gain.

Local recipes are dated reproducibility profiles, not promises about current apps or future models. Check mutable facts when they affect a decision, preserve working versions for recovery, and revise defaults when capabilities or observed outcomes change. The bundled CLI is `scripts/studio.py`. Configuration comes from `ANIMATION_CONFIG`, then private `scripts/local.json`, then portable `scripts/local.example.json`. Optional browser pixel checks use `scripts/check_motion.mjs`; they test sampled seek behavior, not artistic quality. See [portable setup](references/portable-setup.md). The [historical recipes](references/studio-recipes.md) are optional reproduction detail, not the required workflow.
